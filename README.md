# QQ 酒馆桥接 (QQ ↔ SillyTavern)

把酒馆（SillyTavern）里**某一个对话窗口**通过你的 QQ 小号，桥接到一个指定的 **QQ 好友私聊**。
效果：

- 酒馆里角色（AI）的回复 → 自动发到你的 QQ 好友
- 你在 QQ 好友里发的消息 → 自动作为「用户消息」发回酒馆并触发 AI 回复

于是你可以用手机 QQ 远程和酒馆里的角色聊天，一次只桥接一个对话窗口。

## 架构

```
QQ 好友  <--私聊-->  NapCat(正向WebSocket/OneBot v11)  <--ws-->  bridge.js  <--ws-->  酒馆扩展(qq-bridge)
```

- **NapCat**：登录你的 QQ 小号，提供 OneBot v11 正向 WebSocket（默认 `ws://127.0.0.1:3001`）。
- **bridge.js**（本项目）：Node.js 桥接服务，左边连 NapCat，右边开本地 WS 给酒馆扩展（`ws://localhost:8787`）。
- **qq-bridge 扩展**（本项目 `extension/` 目录）：装在酒馆里，负责读取/注入对话消息。

> 兼容性：扩展用「相对路径 + 动态导入 + 多路径回退」加载酒馆 API，兼容安装在 `third-party/` 或内置 `extensions/` 两种位置，并兼容 1.19.x。

## 一、准备 QQ 小号 + NapCat

> 强烈建议用 **QQ 小号** 做机器人账号，避免主号风控。

1. 下载并安装 NapCat（Windows 一键包，解压后运行 `napcat.bat`；或按官方文档安装）。
2. 启动后用手机 QQ 扫码登录小号。
3. 打开 NapCat 的 **WebUI**（默认 `http://127.0.0.1:6099`），进入「网络配置」→「新建」：
   - 类型：**WebSocket 服务器**（正向 WS）
   - Host：`127.0.0.1`
   - Port：`3001`
   - 消息格式（messagePostFormat）：`array`
   - 上报自身消息（reportSelfMessage）：**关闭**
   - Token：自己定一段字符串（也可留空；若填了，记下来填进下面的 `config.json`）
4. 保存，确认该 WS 配置已启用。

## 二、安装并配置桥接服务

需要 Node.js（本项目已在 Node 22 验证）。

```bash
cd qq-tavern-bridge
npm install
```

编辑 `config.json`：

```json
{
  "napcat": {
    "wsUrl": "ws://127.0.0.1:3001",
    "accessToken": ""            // 与 NapCat 里设的 Token 保持一致（没设就留空）
  },
  "bridge": { "wsPort": 8787, "heartbeatMs": 20000 },  // wsPort: 本地端口；heartbeatMs: 服务端心跳间隔(ms)，用于空闲时保活连接（详见下方「端口说明」）
  "qq": {
    "botQQ": 0,                  // 小号 QQ，仅备注用，可留 0
    "targetUserId": 123456789    // 改成你想桥接的「好友」QQ 号（必须填！）
  }
}
```

启动桥接服务（保持运行，不要关掉窗口，最小化即可）：

```bash
npm start
# 看到 "[bridge] 酒馆桥接 WS 服务已启动: ws://localhost:8787" 即成功
```

可选：自测（用假 NapCat + 假酒馆客户端验证路由）：

```bash
npm test
```

### 端口说明（在哪里确认、改了要同步哪里）

- 桥接服务监听的端口由 `config.json` 里的 `bridge.wsPort` 决定，**默认 8787**。
- 酒馆扩展那边连的地址默认是 `ws://localhost:8787`，可在扩展面板的「桥接地址」输入框里改（会记到浏览器本地，下次自动填）。
- **两边都得一致**：如果你把 8787 改成了别的端口，必须：
  1. 改 `config.json` 的 `bridge.wsPort`，并重启 `bridge.js`；
  2. 在酒馆扩展面板的「桥接地址」里也改成同样的 `ws://localhost:<新端口>`。
- **怎么确认实际用的端口**：
  - 看 `bridge.js` 启动时的那行日志：`[bridge] 酒馆桥接 WS 服务已启动: ws://localhost:8787`；
  - 或在命令行执行 `netstat -ano | findstr 8787`，有 `LISTENING` 就说明正在监听；
  - 或直接打开 `config.json` 看 `bridge.wsPort`。

## 三、把扩展装进酒馆（重点：文件夹怎么放）

本项目里有一个 `extension/` 文件夹，它**只是一个打包容器**，里面装着扩展的 4 个文件：

```
qq-tavern-bridge/extension/
├── manifest.json   ← 扩展清单
├── script.js       ← 扩展主逻辑
├── index.html      ← 设置面板
└── style.css       ← 样式
```

你要做的，是**把 `extension/` 里面的这 4 个文件，复制到你自己在酒馆里新建的一个文件夹里**——
**不是**把整个 `extension/` 文件夹塞进去（那样会多套一层，酒馆找不到）。

### 正确步骤

1. 进入酒馆的安装目录，找到扩展目录：
   ```
   SillyTavern/public/scripts/extensions/third-party/
   ```
2. 在那里**新建一个文件夹**，名字随意（例如 `qq-bridge`）。
3. 把 `extension/` 里的 4 个文件复制进这个新建文件夹。

### 最终结构应该是这样（✅ 正确）

```
SillyTavern/public/scripts/extensions/third-party/qq-bridge/
├── manifest.json
├── script.js
├── index.html
└── style.css
```

### 错误示范（❌ 不要让结构变成这样）

```
SillyTavern/public/scripts/extensions/third-party/qq-bridge/extension/manifest.json
                                                                  ├── script.js
                                                                  ├── index.html
                                                                  └── style.css
```
（错误点：多套了一层 `extension/`，酒馆扫描不到。）

> 提示：文件夹名字（`qq-bridge`）就是扩展的内部标识，随意起都行；但里面 4 个文件名不要改，
> `manifest.json` 里写死了 `js: "script.js"`、`css: "style.css"`。

### 启用扩展

1. **彻底关闭酒馆再重启**（不是只关浏览器标签，要把运行酒馆的命令行窗口也关掉再重开）。
   酒馆只在启动时扫描扩展目录，运行中放入的文件不会自动出现。
2. 浏览器里按 **Ctrl + F5** 强制刷新。
3. 打开「扩展管理 / 已安装扩展程序」，找到 **QQ 酒馆桥接**，把开关打开。
4. 打开你想桥接的那个**角色对话窗口**。
5. 在扩展设置面板（扩展管理里找到「QQ 酒馆桥接」的折叠项并展开）点 **「绑定当前对话并启用」**。
6. 状态点变绿（已连接）即可。

之后用你的目标好友 QQ 给小号发消息，就能在酒馆里看到角色自动回复，回复也会回传到 QQ。

7.此后再次启动，只需先启动napcat，再双击start.bat即可s

## 三·A、如何让桥接「息屏/后台也长时间不断连」（关键）

你的用法是「手机远程发消息、电脑没人管」，所以**不断连**比「断了再救」重要得多。

断连的根本原因**不是网络**，而是：**电脑息屏 / 闲置后，浏览器（Edge/Chrome）会把酒馆标签页「冻结」或「丢弃」（Sleeping tabs / 效能模式 / 内存节省），连在里面的 WebSocket 随之被掐掉。** 你试过的「关闭屏幕后最大化窗口」**没用**——不可见的页面照常被冻结。

要让它稳定在后台跑一整天，请三层一起做：

### 1) Windows 电源：只关屏，不睡眠
设置 → 系统 → 电源和睡眠：
- 「关闭显示器后」：随意（你原来设的“不进行任何操作”即可）
- 「睡眠」：**设为「从不」**（笔记本还要把「使用电池 / 接通电源」两项都设「从不」）
这样电脑一直醒着，后台进程不会被系统挂起。

### 2) Edge：关闭「睡眠标签」和「效能模式」
地址栏打开 `edge://settings/system`：
- 关掉「使用睡眠标签 / Sleeping tabs」
- 关掉「效能模式 / Efficiency mode」
（可选）地址栏打开 `edge://discards`，找到酒馆那个标签页，点「永不丢弃 / Never discard」
这样 Edge 不会主动把酒馆标签页冻结或丢弃。

### 3) 扩展自带的「静音保活」（已默认开启）
扩展设置面板里有一项 **「防息屏断连（静音保活）」**（默认勾选）。
原理：浏览器不会冻结「正在播放媒体」的标签页。你点「绑定并启用」时，扩展会在后台**循环播放一小段静音音频**（数据全为 0，完全听不到声音），让标签页始终处于「媒体播放中」状态，Edge 就不会去冻它，WebSocket 也就一直活着。
- 取消勾选即可关闭（但不建议，断连概率会上升）。
- 注意：自动播放需要一次用户手势，所以**第一次「绑定并启用」必须由你手动点一次**；之后页面即使自动重载，浏览器通常也会因「媒体参与度」放行自动播放。

做完这三步，电脑息屏、人外出用手机，桥接也能一整天稳定不断连；万一极端情况下标签页仍被冻结，下方 FAQ 的「重连 + 漏发补发」机制还会兜底，把断连期间漏掉的回复补给你。

> 终极方案（可选）：若你希望「彻底不依赖浏览器标签页」——例如电脑重启、酒馆网页崩溃后也能无人值守自动恢复——可把桥接逻辑改成由常驻 Node 服务**直接调用酒馆本地 API**（不再需要浏览器扩展）。需要的话我可以帮你做这一版。

## 四、使用注意

- **一次只桥接一个窗口**：绑定的是「当前激活对话」。切换酒馆对话后，想换窗口就重新点绑定。
- 只有**角色的回复**会被转发到 QQ（不会把你在酒馆里手打的用户消息也转发，避免冗余）。
- QQ 里发来的消息会作为用户消息触发一次新回复，形成闭环；NapCat 侧已关闭上报自身消息，不会回环。
- 桥接服务、NapCat、酒馆三者都跑在同一台机器上（本地回环）。若酒馆在别的机器用浏览器访问，需要把 `bridge.wsPort` 暴露/改地址。

## 常见问题

- **扩展「加载失败：[object Event]」**：通常是扩展脚本加载/解析失败。先按 F12 看浏览器控制台红字。本版扩展已改用动态导入 + 多路径回退，并改用全局 `SillyTavern.getContext`，可兼容 1.19.x；若仍失败，检查文件是否放对位置（见上方「三」），以及 `script.js` 能否被访问到。
- **桥接服务连不上 NapCat**：确认 NapCat 正向 WS 已启用且端口是 3001；若设了 Token，两处一致。
- **酒馆扩展连不上桥接服务**：确认 `bridge.js` 正在运行；酒馆浏览器能访问 `localhost:8787`（同机）；确认「桥接地址」与 `config.json` 的端口一致。
- **QQ 收不到回复**：检查 `qq.targetUserId` 是否填成好友 QQ 号；确认小号已登录且未被风控。
- **空闲一段时间（甚至开着屏幕）扩展显示「已断开」，一旦操作又自动连上**：这通常**不是酒馆核心代码的问题**，而是浏览器在标签页长时间空闲/切到后台时，被「内存节省 / 标签冻结（Tab Freezing / Memory Saver）」悄悄掐掉这条 WebSocket 连接，而且**不会发出 `close` 事件**——扩展只靠 `readyState` 判断时会误以为还连着，于是干等，直到你切回标签页触发重连。本版已针对性加固：
  1. **双向应用层心跳**：扩展每 15 秒向桥接服务发 `{type:'ping'}`，服务端回 `{type:'pong'}`；以「最近一次收到任何消息的时间」作为**真实存活信号**。
  2. **静默断连检测**：超过 45 秒没收到任何服务端消息，就**主动 `close()` 强制重连**（绕开 `readyState` 的欺骗性 `OPEN`）。
  3. **服务端更宽容**：连续 3 次漏 pong（约 60 秒）才终止连接，不再一抖就掐。
  4. 扩展在页面可见（`visibilitychange`）、窗口聚焦（`focus`）、网络恢复（`online`）时**立即重连**。
  这样即使标签页被冻结，一旦你切回去也会**立刻**自动恢复；空闲时也不再无故掉线。
  - 想进一步降低掉线：浏览器里关闭「内存节省程序 / Memory Saver」（Chrome 设置 → 性能和电池 / 系统），或把酒馆标签页**固定（pin）**住，可减少被冻结/丢弃的概率。
  - 若机器息屏会进入真正的休眠，连接仍会断，但唤醒后会立刻自动恢复，属正常现象。
  - 上述「心跳 / 重连 / 补发」是兜底，**源头预防请看上方「三·A、如何让桥接息屏/后台也长时间不断连（关键）」**：把 Windows 设为不睡眠、Edge 关掉睡眠标签/效能模式、并保留扩展里默认开启的「静音保活」——三者一起做，标签页就不会被冻结，连接自然不断。

- **「屏幕关着时发的消息，等亮屏后发现酒馆已经回复了、但没转发到 QQ」**：这是早期版本的真实 bug——回复是在扩展**断连的那段时间**生成的，生成那一刻 `ws` 还没重连好，于是转发被跳过且再无机会补发。本版已修：
  1. **断连期间漏发的回复会自动补发**：扩展记录「已转发的最大消息下标」，重连成功后扫描当前对话里比基线更新的 AI 回复，把漏掉的回复补发给 QQ（重连后约 1.5 秒内完成）。
  2. **你离线时发的 QQ 消息不会丢**：若酒馆客户端当时不在线，桥接服务会先把 QQ 私聊消息**缓存**起来，等酒馆重连后自动补推过去。
  3. 启用/切换对话时会先校准基线，所以**不会**把已有聊天历史当成新消息重复刷给 QQ。
  - 桥接命令行里若看到 `补推离线期间缓存的 N 条 QQ 消息`，说明上述第 2 条正在生效，属正常。

- **桥接命令行里 `已断开 (code=…)` 的 code 含义**（仅供参考，不影响自动重连）：
  - `1005`：客户端「干净关闭但没发关闭帧」（多见于标签页被后台冻结/丢弃后）。
  - `1006`：异常断开（多为手动刷新页面、或旧连接被新连接清理）。
  - `1001`：客户端「正在离开」（多发生在你切回/打开酒馆标签页那一刻，旧连接被标记为离开并触发重连）。
  - 这些都是浏览器在低功耗/后台态下的正常行为，新连接会自动建立，无需手动干预。
